This one is all about speed. ⚡ Nothing new to click, everything you already click is faster.

## 🎞️ Timeline: events land the moment they happen

The timeline used to pace new cards in one at a time, about three a second, and quietly dropped anything past 60 in the queue. Nice to watch, terrible when an app fires 10 events on a screen load and you wait 3 seconds for the last one. 😬

Now a whole batch comes in together as one spring, and nothing is dropped any more. Small groups still get the animation (that's the whole point of the timeline); a flood of 20+ cards just appears, because nobody can follow 20 cards sliding in anyway. Cards are flat now too, no drop shadow, which is both the look the rest of the app has and a lot cheaper to draw. 🃏

## 📋 List: 100,000 rows without breaking a sweat

The list is now a proper AppKit table under the hood. Before, every incoming batch made SwiftUI compare all rows in the buffer again to figure out what changed. With a full 100k buffer that was the single biggest cost in the app, and memory ballooned past 2 GB. 🎈

Same table, same columns, same selection and right-click menu, but a batch of new rows is now just "there are 12 more rows". Memory for a full buffer went from 2.3 GB to about 650 MB, and when you scroll up to read something, the row under your cursor stays put while the buffer trims old events off the top. 📌 Column widths are remembered between launches as a bonus.

## 🔎 Search that keeps up with typing

Typing into the filter field ran a full pass over every event on every keystroke, on the main thread, lower-casing each message (including 64 KB network bodies) as it went. 🐢 Now:

- Each event gets its lower-cased search text once, in the background, when it arrives.
- Keystrokes are debounced, so fast typing runs one pass instead of six.
- Big buffers filter off the main thread, and typing one more character narrows the previous result instead of starting over.

Sidebar counts also stopped re-sorting ten times a second. They tick up calmly a few times a second now instead of flickering. 🧭

## 🌐 Network requests without the hitch

A big JSON response was being inflated and pretty-printed on the main thread the moment it finished, which showed up as a stutter. That now happens off the main thread before the card is handed over. 🛠️ Image, video and font bodies are no longer kept in memory (just a small prefix), and there's a 256 MB cap on stored bodies overall, so a long session of asset traffic through the proxy can't eat your RAM. 🧠

## 🔋 Idle means idle

LogLens was running `simctl` and `devicectl` every 8 seconds forever, even hidden in the background. It now only refreshes the simulator list while it's the active app, and skips the slow device scan entirely. Background CPU is 0%. 😴

## 🔬 Under the hood

- Timestamps are parsed by hand instead of through `DateFormatter`: about 200× faster per line, and microsecond-precise instead of millisecond. ⏱️
- Repeated strings (process, subsystem, category) are shared between events instead of copied per event.
- A batch reaches the screen ~16 ms after its first line arrives instead of waiting for a 100 ms timer.
- New dev flag: `--replay <file.ndjson> --rate N` feeds a captured `log stream` file through the real pipeline for reproducible profiling, and the hot paths carry signposts for Instruments. 🧪

Measured on the same replay: list view at 2,000 events/s went from 40% CPU and 1 GB to 24% and 290 MB; the timeline shows every event at 200/s at 12% CPU where it used to drop most of them at 18%. 📉
