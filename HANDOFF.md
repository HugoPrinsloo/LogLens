## What this app is

LogLens is a macOS 15 SwiftUI app (owner: Hugo Prinsloo) that live-captures OSLog output from iOS simulators or the Mac (`/usr/bin/log stream --style ndjson`, or `xcrun simctl spawn <udid> log stream`) and presents events for debugging analytics/instrumentation. Two views: a classic table and an animated vertical timeline where event cards spring in from the bottom. Hugo primarily uses it to watch analytics events (impressions, clicks, EIDs) from the "Over" app in the simulator.

## Architecture cheat sheet

- `LogLens/App/LogLensApp.swift` — `@main`, WindowGroup, Capture command menu (⌘R record, ⌘K clear, ⇧⌘T auto-scroll, ⌥⌘I inspector).
- `LogLens/Store/EventStore.swift` — `@MainActor @Observable`, the single hub. `entries` (ring buffer, `maxEntries` 100k), `filtered` (what UI renders), facet counts, `filter: LogFilter`, `selection` (**`didSet` force-opens the inspector — timeline code must never set it**), `viewMode` (table/timeline, persisted; a stale "network" value falls back to table), `timelineExpandAll` (persisted), `timeline: TimelineFeed`, `lanes: [TimelineLane]`. Batches arrive via `LogStreamer.onBatch` every 100 ms into `append(_:)` — the single funnel that also feeds timeline + lanes. `refilter()`/`clear()` reset feeds. Persistence = manual `UserDefaults` in `didSet` (keys: scope, customPredicate, captureLevel, maxEntries, viewMode, timelineExpandAll). **didSet doesn't fire in init** — init restores manually.
- `LogLens/Store/TimelineFeed.swift` — pacing engine. Queues entries, reveals on a spring at 350→80 ms cadence, skips ahead past a 60-deep queue (`skipped` count), caps `visible` at 200 cards. Reveal animation `.spring(duration: 0.35, bounce: 0.15)` **must match** the scroll animation in `TimelineScroll` or the glide stutters.
- `LogLens/Store/TimelineLane.swift` — lane = facet set + own feed + cached matcher (global filter with facets swapped).
- `LogLens/Store/LogFilter.swift` — `Facet` enum (process/subsystem/category), `makeMatcher`. Plain sidebar click toggles (checkbox semantics, Hugo's request); "Only This" in the context menu is the exclusive-within-kind path.
- `LogLens/Models/` — `LogEntry` (id-only equality), `ParsedMessage` (title/summary/fields/groups/freeText), `LogLevel` (color/symbol), `EventSemantics.swift` (derived `eventType`, `eid`, `EventTypeStyle` colors: **impression=blue, click/tap/select=green** per Hugo, rest orange/red/purple/teal…, FNV-1a fallback — never `String.hashValue`, it's seeded per launch; SF Symbol per type).
- `LogLens/Parsing/MessageParser.swift` — heuristics: `Key: Value` lines, Swift-description groups, dotted titles (`cart.checkout_button.click` → type "click").
- `LogLens/Views/` — `ContentView.swift` (NavigationSplitView + toolbar incl. view-mode segmented control, Split + Expand All toggles in timeline mode, inspector gated to table mode), `Table/EventTableView.swift`, `Timeline/EventTimelineView.swift` (`TimelineScroll` reusable column, `IncomingIndicator` pulsing dots + "+N incoming"), `Timeline/TimelineCard.swift` (`TimelineRow` centered connector, card with icon chip + tag capsule), `Components/` (`LevelBadge`, `TagBadge`, `KeyValueGrid`), `Sidebar/SidebarView.swift`, `Detail/EventDetailView.swift`.

## Dev workflow (all verified this session)

- Project is **XcodeGen-generated**: after adding/removing files run `xcodegen generate` (whole-folder glob picks new files up). Ignore SourceKit "Cannot find type" diagnostics — they're stale-index noise; the build is the arbiter.
- Build: `xcodebuild -project LogLens.xcodeproj -scheme LogLens -configuration Debug -derivedDataPath build build`
- Run for testing: `killall LogLens; open build/Build/Products/Debug/LogLens.app --args --record` (`--record` auto-starts capture on the booted simulator; add `--split` for pre-split timeline).
- Generate real events: `xcrun simctl terminate booted com.gopotluck.over; xcrun simctl launch booted com.gopotluck.over` — relaunching the Over app produces a burst of ~280 events including EventBus impressions.
- Visual verification: find the window id with a small `swift -e` CGWindowList snippet (owner == "LogLens"), then `screencapture -o -x -l<id> out.png` and read the image. Fails if the window is on another Space.
- Release: `./scripts/release.sh <version>` — needs a **clean tree**; sets version in project.yml, archives, Developer ID signs (cloud, team 7VT5H6VPXH), notarizes zip+dmg (keychain profile `LogLens-Notary`), commits "Release vX", pushes, publishes GitHub release. Takes ~5–10 min; run in background.

## Network inspector MVP (built 2026-08-28, uncommitted, not yet shown to Hugo)

Proxyman-style zero-code capture of simulator HTTP(S) traffic with full bodies. No SDK, no app changes. Originally a third view mode; **removed 2026-08-28 evening** — see "Single recording" above. The internals below still apply.

**How it works (files under `LogLens/Network/` + `Store/NetworkStore.swift` + `Views/Network/`):**
- `CertificateAuthority.swift` — P-256 root CA persisted at `~/Library/Application Support/LogLens/CA/LogLens-Root-CA{,-key}.pem` (10 y). Mints per-host leaf certs (397-day validity, SAN, serverAuth) and caches one `NIOSSLContext` per host. Server + client TLS contexts advertise ALPN `http/1.1` only → never HTTP/2.
- `ProxyServer.swift` — SwiftNIO forward proxy on `127.0.0.1:9095` (port in Settings). `ProxyHTTPHandler` (`.plain` mode) handles absolute-URI requests and CONNECT; on CONNECT it either (a) answers 200 and swaps the pipeline to `NIOSSLServerHandler` + fresh HTTP codec + a `.tls` handler that relays request/response parts to an upstream `ClientBootstrap` on the **same event loop**, or (b) opens an opaque `TunnelRelayHandler` byte pump. Bodies stored up to 4 MB (`maxStoredBody`, truncation flagged). `Accept-Encoding: br/zstd` is rewritten to `gzip, deflate` so bodies stay readable; `BodyDecoder` inflates with zlib and pretty-prints JSON for display. Handshake failures with no request seen are reported as a failed `CONNECT` row ("probably pins its certificate"). `NIOSSLError.uncleanShutdown` from upstream is treated as EOF, not an error.
- `ProcessLookup.swift` — libproc scan mapping the client's loopback source port → PID → executable path (~7 ms worst case, cached). `isSimulator` = path contains `/CoreSimulator/` (apps and runtime daemons like `storekitd`, `nsurlsessiond` both match).
- **Decrypt policy** (`DecryptPolicy`, persisted `networkDecryptPolicy`, default `simulatorOnly`): only simulator processes are MITM'd and recorded; all other Mac traffic is tunnelled untouched and **not recorded** — so Mac browsing keeps working during capture without trusting the CA on the Mac. `everything` needs "Trust on This Mac…" (`security add-trusted-cert` into the login keychain, one password prompt). `nothing` = tunnel-only.
- `SimulatorTrust.swift` — `xcrun simctl keychain <udid> add-root-cert` into every booted simulator on start (skipped when `networkCAInstalledSimulators[udid]` already holds this CA's fingerprint; "Reinstall" forces it). Silent, no prompts, no app restart needed.
- `SystemProxy.swift` — the reliability piece. `apply(port:)` snapshots web+secure proxy (enabled/server/port) of every enabled `networksetup` service, **persists the snapshot to UserDefaults before touching anything**, spawns a detached `/bin/sh` watchdog (`while kill -0 <pid>; do sleep 1; done; networksetup …restore…`) and only then sets the proxy. `restore()` runs on Stop, on `NSApplication.willTerminateNotification` (synchronous, `queue: nil`), and on SIGTERM/SIGINT/SIGHUP (DispatchSource → stop → exit). `recoverFromPreviousRun()` at launch re-applies a leftover snapshot. **Verified:** normal quit restores in <2 s; `kill -9` → watchdog restores within ~1–4 s; the pre-existing disabled `127.0.0.1:9090` entry on Wi-Fi (another tool's leftover) is preserved exactly.
- `NetworkStore` — `@MainActor @Observable`; `transactions`/`filtered` (cap 10k), host/process facet counts, `searchText`/`hostFilter`/`processFilter`, `selection` (didSet opens inspector, same rule as EventStore), `policy`, `port`. `start()` = CA → proxy → simulator trust → system proxy (rolls back on failure). Events arrive on main via `ProxyServer.onEvent` (`.began`/`.updated` full-struct replacement; body chunks accumulate silently, only head/end emit).
- UI: `NetworkView` (8-column `Table`: Time/Method/Status/App/Host/Path/Size(+type)/Duration — **SwiftUI `Table` with 9 columns rendered rows misaligned with the header on macOS 26; 8 works. Don't add a 9th column without re-checking.** `scrollTo` must use `.bottomLeading`, `.bottom` scrolls horizontally), `NetworkDetailView` (Response/Request/Overview tabs, header grids via `KeyValueGrid`, `BodyView` with Pretty/Raw JSON toggle, 200 KB display cap, hex preview for binary, cURL/URL/body copy), `NetworkSidebar` (proxy card with Record/Stop, certificate menu, policy picker; Apps/Hosts facets, single-select toggle), `NetworkBadges` (method/status colors: GET blue, POST green, PUT orange, PATCH purple, DELETE red; 2xx green/3xx blue/4xx orange/5xx red). Toolbar, status bar, ⌘R/⌘K/⇧⌘T/⌥⌘I are mode-aware (`ContentView`, `LogLensApp`). Settings → "Network Proxy" section.
- SPM deps (first in the project; `packages:` in `project.yml`): swift-nio 2.101, swift-nio-ssl 2.37, swift-certificates 1.19, swift-crypto 3.15 (+ transitive asn1/atomics/collections/system). Resolved into `build/SourcePackages`. `zlib` is imported directly (SDK module).

**Dev flags:** `--network` opens in network mode and auto-starts the proxy; `--network-dump <path>` appends one JSON line per finished transaction (how the core was proven before UI existed); `--select-last` keeps the newest request selected (screenshot aid). Verified flow: `scratch/launch.sh`-style `killall LogLens; wait until gone; open … --args --network`, then `xcrun simctl terminate/launch booted com.gopotluck.over` → ~40–60 decrypted requests (api.godaddy.com, braze, firebase, appsflyer, storekitd → amp-api.sandbox.apple.com). **Don't `open` the app while the old instance is still shutting down** — `open` re-activates the dying instance and nothing launches.

**Certificate trust & pinning (learned the hard way, 2026-08-28 afternoon):** Hugo saw a wall of "TLS handshake rejected … EOF during handshake" rows for *every* host. Cause: the simulator's trust store had lost the CA (an "Erase All Content and Settings" / keychain reset wipes it) while `networkCAInstalledSimulators` said it was installed, so the install was skipped. Fixes now in place: (1) `SimulatorTrust.installInBootedSimulators` **always** re-adds the CA on Record (idempotent, ~1 s); (2) `ProxyServer.sawSuccessfulHandshake` gates pin detection — a rejection before any successful decrypt fires `onTrustProblem` → `NetworkStore.handleTrustProblem` reinstalls the CA (throttled 20 s) and the row says "simulator doesn't trust the certificate yet — reinstalling"; (3) only after decryption has worked does a rejection mark the host as pinned: `learnPinned` adds it to `bypassHosts` (persisted `networkBypassHosts`, shown via sidebar Certificate ▸ "Forget Pinned Hosts (n)", per-row context menu "Don't Decrypt / Try Decrypting Again"), and later CONNECTs to it are tunnelled untouched so the app keeps working (row: lock icon + note). Built-in always-tunnel list `ProxyServer.builtInBypass` (`*.push.apple.com`, `gsa.apple.com`, `*.ls.apple.com`, `*.icloud.com`, `*.apple-cloudkit.com`, `*.icloud-content.com`). Verified: `xcrun simctl keychain booted reset` mid-capture → next Over launch triggers the reinstall → following requests decrypt; learned list stays empty. A pinned app can only be decrypted by changing the app (debug-build flag to skip pinning / trust user CAs) — the proxy can't "do the handshake" for it.

**Known limits / open items:**
- Cert-pinned apps show as one failed CONNECT row, then tunnelled (see above). `csp.test-godaddy.com` fails with DNS UnknownHost — the Over app's bug, not ours. Port-80 plain HTTP is blocked on Hugo's network, so `curl -x … http://…` tests from the Mac time out even though the plain-proxy path works.
- No backpressure on the relay (fine for API traffic; a huge download through a slow client would buffer in memory).
- Upstream TLS uses system trust; self-signed dev servers will fail (no "ignore upstream cert" option yet).
- WebSockets, HTTP/2 passthrough for tunnels (works, opaque), request rewriting, breakpoints, physical devices: out of scope.
- IP-literal CONNECT targets get an iPAddress SAN but no SNI on the upstream leg.
- Hugo hasn't reviewed the UI. Likely asks: body search, per-request timeline lane, export HAR.

## Network requests in the log views + "Heal" (2026-08-28, uncommitted)

- **Heal** (`NetworkStore.repair()`): toolbar button (`bandage.fill`, Network mode) and sidebar Certificate ▸ "Heal Connection". Stops the proxy (restoring the Mac proxy), forgets learned pinned hosts, drops the CA-installed cache, then `start()` again → CA re-added to every booted simulator, proxy restarted, system proxy re-applied. Hugo asked for "a button that force-restarts whatever it needs".
- **Network cards in the timeline/table**: every finished transaction (`NetworkStore.onFinished`, wired in `LogLensApp.init`) becomes a `LogEntry` via `LogEntry.network(_:)` (`Models/NetworkLogEntry.swift`) and goes through `EventStore.appendNetwork` → the normal `append` funnel, so it gets facets (subsystem **"Network"**, category = host, process = app), search, lanes, star, copy-as-image. IDs are `1_000_000_000 + tx.id`. `LogEntry.isNetwork` marks them; the **"Network" toolbar toggle** (`EventStore.showNetworkEvents`, persisted, default on) hides them via `makeMatcher` (also applied to lane matchers). Card: title `GET host/path`, badge from the `Action` field (HTTP method — colors/symbols added to `EventTypeStyle.fixed`/`symbols`), fields Status/Duration/Size/Host/Path/Query/Content/Error, freeText = "↑ Request body" preview (POST/PUT/PATCH) and "↓ Response body" preview (pretty JSON, 24 lines each). **Don't name a field "Type"** — `derivedEventType` reads `type` before `action` and the badge becomes the content type (that bug shipped for ~10 minutes as a "GIF" badge). Hugo immediately used Split with lanes Network | EventBus — that's the intended workflow.
- Card polish (Hugo's feedback): `LogEntry.network: NetworkCardData?` carries method/status/bodies (decoded, pretty JSON, 64 KB cap) so `TimelineCard` renders **`OutcomeBadge`** (✓ 200 green / ✕ 4xx orange / ✕ 5xx or FAILED red / TUNNEL gray) next to the method tag, and request/response bodies in **`JSONText`** boxes (`Views/Components/JSONText.swift`: monospaced, `JSONHighlighter` colours keys blue / strings coral / numbers lavender / literals amber, 40-line cap with "Show all", copy button). `parsed.freeText` is empty for network entries; `message` still holds the body text for search/inspector.
- Dev flag `--proxy` starts the proxy without switching to the Network view (for timeline screenshots with both captures running).
